# Correlation Algorithms

The mathematical core of Sentinel's value proposition is its ability to correlate independent, medium-severity signals into critical attack vectors.

## The Tri-Boundary Correlation Matrix

Let $E$ represent the set of all findings generated by the engines, where:
- $C \subset E$ represents findings from CodeSentinel.
- $W \subset E$ represents findings from WebSentinel.
- $M \subset E$ represents findings from MCPSentinel.

A standard SAST or DAST tool evaluates $C$ or $W$ in isolation. Sentinel evaluates the intersection $C \cap W \cap M$ using predefined combinatorial signatures.

### Example: `platform-mcp-exposure`

The platform orchestrator implements the following logical proof to identify a P0 attack path:

1. **Assertion 1 (Web):** $\exists w \in W$ such that $w.\text{ruleId} = \text{"ai-widget"}$
   *(The frontend exposes an AI chat interface to the public).*

2. **Assertion 2 (Code):** $\exists c \in C$ such that $c.\text{ruleId} = \text{"missing-auth"}$
   *(The backend API route lacks authentication middleware).*

3. **Assertion 3 (MCP):** $\exists m \in M$ such that $m.\text{ruleId} = \text{"mcp-privilege-analysis"}$
   *(The connected AI agent possesses an unconstrained tool, such as `execute_query`).*

**Conclusion:** 
If $(Assertion 1 \land Assertion 2 \land Assertion 3)$ evaluates to True, the orchestrator synthesizes a new composite finding $F_{new}$ with `severity = CRITICAL`.

This combinatorial approach allows Sentinel to mathematically prove the existence of multi-hop vulnerabilities that are invisible to single-domain parsers.
