# CLI Reference — Commands & Options

Sentinel provides a modern, Nmap-inspired CLI with short flags, an interactive wizard, and config file support.

## Installation

```bash
# Global install (recommended)
npm install -g @sentinel/platform

# Or link locally from the monorepo
npm link ./packages/platform
```

After installation, the `sentinel` command is available globally.

---

## Commands

### `sentinel scan [url]` *(Default Command)*

The primary command. Scans a web application, backend source code, and MCP server simultaneously.

**If no arguments are provided**, Sentinel launches the **Interactive Wizard** with Express Mode and Advanced Mode options.

#### Syntax
```bash
sentinel scan <url> [options]
```

#### Positional Argument
| Argument | Description |
| --- | --- |
| `url` | The URL of the web application to scan (e.g., `http://localhost:3000`). |

#### Short Flags (Nmap-Style)
| Short | Long | Description | Default |
| --- | --- | --- | --- |
| `-p` | `--project <id>` | Project ID for reports and correlation. | Auto-generated |
| `-m` | `--mcp <cmd>` | Command to start the backend MCP server. | — |
| `-y` | `--authorized` | Confirm legal authorization to test the targets. | `false` |
| `-c` | `--code <path>` | Path to backend source code for CodeSentinel. | — |
| `-A` | `--ai` | Enable Supercharged AI Auditing (Ollama/Gemini). | `false` |
| `-f` | `--format <fmt>` | Output format: `cli`, `json`, `html`, `md`. | `cli` |
| `-o` | `--out <file>` | Write output to a file. | — |
| `-E` | `--executive-report <dir>` | Generate AI executive HTML report in the given directory. | — |

#### Advanced Options
| Long | Description | Default |
| --- | --- | --- |
| `--mcp-name <name>` | Stable MCP target name for correlation. | — |
| `--allow-local` | Allow scanning localhost/private IPs. | `false` |
| `--budget <num>` | Max number of AI requests per scan. | `5` |
| `--ai-model <model>` | LLM model to use. | `llama3` |
| `--ai-provider <prov>` | AI provider (`ollama`, `mock`). | `ollama` |
| `--ai-url <url>` | Ollama API URL. | `http://localhost:11434` |

### `sentinel run <configFile>`

Run a scan using a pre-saved JSON configuration file.

```bash
sentinel run sentinel.config.json
```

This is the recommended way to run Sentinel in CI/CD pipelines. The config file is generated by the interactive wizard or `sentinel init`.

---

### `sentinel init`

Launch the interactive wizard to generate a `sentinel.config.json` file.

```bash
sentinel init
```

This command:
1. Auto-detects the start command from `package.json`, `docker-compose.yml`, or common entry points.
2. If auto-detection fails, offers **Gemini AI** to analyze the workspace and suggest the command.
3. Saves the config file for future 1-click runs.

## Interactive Wizard (Express Mode)

When you run `sentinel` or `sentinel scan` with no arguments, the interactive terminal wizard launches:

```
┌  Sentinel Tri-Boundary Orchestrator  v0.1.0
│
◆  How would you like to configure Sentinel?
│  ● 🚀 Express Mode (1-Click, Auto-Detect)
│  ○ ⚙️ Advanced Mode (Configure all settings)
│
◇  Analyzing workspace...
│  Detected start command: npm start
│
◇  Web Application URL:
│  http://localhost:3000
│
◇  Authorization Check (REQUIRED)
│  By continuing, you confirm you have legal authorization.
│
└  Configuration complete! Starting Sentinel analysis...
```

**Express Mode** reduces the setup to just confirming the URL. Everything else is auto-detected. **Advanced Mode** lets you configure every setting individually.

## Usage Examples

### 1. Fastest Possible Scan (Express Mode)
```bash
sentinel
# → Select Express Mode → Confirm URL → Done!
```

### 2. Quick CLI Scan (Nmap-Style)
```bash
sentinel scan http://localhost:3000 -m "node server.js" -y -c ./src
```

### 3. Full Scan with AI and Executive Report
```bash
sentinel scan http://staging.app.com -m "node server.js" -y -c ./backend -A -E ./reports -f html -o scan.html
```

### 4. CI/CD Pipeline (Config File)
```bash
sentinel run sentinel.config.json --format md >> $GITHUB_STEP_SUMMARY
```

### 5. Code-Only Scan (No Web/MCP)
```bash
sentinel scan http://localhost:3000 -m "echo noop" -y -c ./src
```

## Exit Codes

| Code | Meaning |
| --- | --- |
| `0` | Scan completed successfully (findings may exist). |
| `1` | Scan failed due to configuration error or authorization rejection. |
